# 商品庫存重構完成總結

## 重構概述
本次重構將商品庫存功能從商品表獨立出來，改為按店面進行管理。庫存資料存儲在新的 `StoreToStock` 表中，實現了庫存與店面的綁定。

## 實作項目

### 1. 後端資料庫模型層 (stock.model.js)
**檔案**: `spine-server/src/models/stock.model.js`

創建了新的 `StoreToStock` 資料表模型，包含以下欄位：
- `id`: 庫存記錄唯一識別碼
- `productId`: 商品 ID
- `productType`: 商品類型 ("Pillow" 或 "Mattress")
- `storeId`: 店面 ID
- `stock`: 庫存數量
- `createdAt`: 創建時間
- `updatedAt`: 更新時間

主要功能方法：
- `getAllStockList()`: 取得所有庫存記錄
- `addStock()`: 新增庫存記錄
- `getStock()`: 取得單一庫存記錄
- `updateStock()`: 更新庫存記錄
- `deleteStock()`: 刪除庫存記錄
- `getStockByProduct()`: 根據商品查詢庫存
- `getStockByStore()`: 根據店面查詢庫存
- `getStockByProductAndStore()`: 根據商品和店面查詢特定庫存
- `upsertStockBatch()`: 批量新增或更新庫存
- `deleteStockByProduct()`: 刪除商品相關的所有庫存記錄

### 2. 後端服務層 (stock.service.js)
**檔案**: `spine-server/src/services/stock.service.js`

實作了業務邏輯處理，包含：
- 基本 CRUD 操作的封裝
- **`getInventoryByStoreManager()`**: 核心方法，根據店長 ID 取得該店長管理店面的所有商品庫存
  - 自動關聯 Store、ProductPillow、ProductMattress 資料表
  - 補充沒有庫存記錄的商品（顯示為 0）
  - 返回完整的庫存清單，按枕頭和床墊分類
- **`getStoresByStoreManager()`**: 取得店長管理的所有店面

### 3. 後端 API 控制器 (stock.api.controller.js)
**檔案**: `spine-server/src/controllers/manager/stock.api.controller.js`

創建了完整的 RESTful API 路由：
- `GET /api/manager/stock/inventory`: 取得當前店長管理店面的所有商品庫存
- `GET /api/manager/stock/stores`: 取得當前店長管理的所有店面
- `POST /api/manager/stock`: 新增庫存記錄
- `PUT /api/manager/stock/:id`: 更新庫存記錄
- `DELETE /api/manager/stock/:id`: 刪除庫存記錄
- `POST /api/manager/stock/batch`: 批量新增或更新庫存
- `GET /api/manager/stock/product/:productId/:productType`: 根據商品取得庫存

所有路由都包含：
- JWT 認證中間件 (`authMiddleware`)
- 店長權限檢查 (`isStoreManager()`)

**路由註冊**: 已在 `spine-server/src/index.js` 中註冊路由

### 4. 前端 API 調用 (stock.js)

所有請求都自動帶入 JWT token。

## 權限控制邏輯

### 店長權限檢查流程
1. 前端攜帶 JWT token 發送請求
2. 後端 `stock.api.controller.js` 解析 token 取得 `userId`
3. 調用 `userToRole.service.js` 的 `isStoreManager()` 檢查是否為店長
4. 若非店長，返回 403 錯誤 "權限不足"
5. 若是店長，調用 `store.service.js` 的 `getStoresByStoreManagerId()` 取得管理的店面
6. 根據店面 ID 查詢 `StoreToStock` 表，關聯商品資料

### 資料關聯流程
```
店長 (userId) 
  ↓ (storeManagerId)
店面 (Store)
  ↓ (storeId)
店面庫存 (StoreToStock)
  ↓ (productId, productType)
商品 (ProductPillow / ProductMattress)
```

## 使用流程

### 店長新增商品時
1. 進入商品新增頁面
2. 填寫商品基本資料（名稱、型號、價格等）
3. 為每個管理的店面設定初始庫存
4. 點擊「新增」按鈕
5. 系統先創建商品，再批量創建庫存記錄

### 店長編輯商品時
1. 進入商品編輯頁面
2. 自動載入商品資料和各店面庫存
3. 修改商品資料或調整各店面庫存
4. 點擊「儲存」按鈕
5. 系統更新商品資料並批量更新庫存記錄

### 查看庫存頁面時
1. 進入商品庫存頁面
2. 系統自動檢查店長權限
3. 載入該店長管理店面的所有商品庫存
4. 按商品分組，顯示各店面的庫存數量
5. 可直接在頁面上編輯庫存數量

## 注意事項

1. **舊資料遷移**: 如果系統已有商品資料，需要將原本商品表中的 `stock` 欄位遷移到 `StoreToStock` 表
2. **預設店面**: 如果商品沒有指定店面，可能需要建立一個「預設店面」或「總倉」的概念
3. **權限擴充**: 未來可能需要支援更細緻的權限控制（如：只能查看、只能編輯等）
4. **效能優化**: 若商品或店面數量龐大，可能需要考慮分頁或快取機制
