[why] 為了提高計算的靈活性和準確性。
[how]

## 問題描述

[尾椎分析頁](../../spine-client/src/pages.spine/manager/AnalysisTail.jsx) 不論是有 [圖片] 或 [還原圖片] 模式，按下 [計算] 按鈕後，首次計算的點位距離為 0。

但 [頸部分析頁](../../spine-client/src/pages.spine/manager/AnalysisSpine.jsx) 卻可正常計算。

---

## 問題原因分析

經過對比兩個頁面的代碼，發現有**兩個主要問題**：

### 問題 1：React 閉包陷阱

**原始代碼：**
```javascript
const buildTailMetrics = (scaleFactor) => {
    const currentScaleFactor = scaleFactor !== undefined ? scaleFactor : scaleFactorState;
    if (points.length < 3) return null;
    const [p1, p2, p3] = points;  // ❌ 直接使用閉包中的 points
    // ... 計算邏輯
};
```

`buildTailMetrics` 函數直接從閉包中讀取 `points` 狀態，導致：
1. 函數在組件初始化時被定義，捕獲的是當時的 `points` 值
2. 當 `handleCalculate` 被調用時，即使 `points` 已更新，函數內部仍可能使用舊值
3. React 的異步更新特性導致首次計算使用初始值（空陣列或預設位置）

### 問題 2：事件對象被誤當作參數使用

**原始代碼：**
```javascript
const handleCalculate = (scaleFactor) => {
    const currentScaleFactor = scaleFactor !== undefined ? scaleFactor : scaleFactorState;
    // ...
};

// 按鈕綁定
<button onClick={handleCalculate}>計算</button>
```

**問題分析：**
- 當按鈕被點擊時，React 會傳入一個 **Event 對象** 作為第一個參數
- `handleCalculate` 函數誤將這個 Event 對象當作 `scaleFactor` 使用
- `scaleFactor !== undefined` 判斷為 true（因為 Event 不是 undefined）
- 導致使用 Event 對象進行計算，產生錯誤結果

**頸部分析頁為何正常？**
```javascript
// 頸部分析頁的 handleCalculate 不接收任何參數
const handleCalculate = () => {
    calculateSpecialLines();
    calculateAllDistancesAndAngles();  // 直接使用狀態中的 scaleFactorState
    setIsCalculated(true);
};
```

## 解決方案

### 修復 1：將 points 作為參數傳入

```javascript
// 修改後
const buildTailMetrics = (scaleFactor, currentPoints) => {
    const currentScaleFactor = scaleFactor !== undefined ? scaleFactor : scaleFactorState;
    const pointsToUse = currentPoints !== undefined ? currentPoints : points;
    if (pointsToUse.length < 3) return null;
    const [p1, p2, p3] = pointsToUse;  // ✅ 使用傳入的參數
    // ...
};
```

### 修復 2：handleCalculate 不接收參數

```javascript
// 修改後 - 不接收參數，直接使用狀態值
const handleCalculate = () => {
    if (points.length < 3) return;

    // 明確傳入當前狀態值
    const metrics = buildTailMetrics(scaleFactorState, points);
    if (!metrics) return;

    // ... 其餘邏輯
};
```

### 修復 3：新增專用的重新計算函數

因為比例尺調整時需要用新的縮放因子重新計算，所以新增一個專門的函數：

```javascript
// 使用指定的縮放因子重新計算（用於比例尺調整時）
const recalculateWithScaleFactor = (scaleFactor) => {
    if (points.length < 3) return;

    const metrics = buildTailMetrics(scaleFactor, points);
    if (!metrics) return;

    const formatDistance = (pxDistance) => formatDistanceWithMode(
        pxDistance,
        showBlankScreen,
        (px) => formatPxCmText(px, scaleFactor)
    );

    setCalculationResults([
        '=== 尾椎量測結果 ===',
        `點 1-2 距離：${formatDistance(metrics.distance12)}`,
        `點 2-3 距離：${formatDistance(metrics.distance23)}`,
        `點 1-3 距離：${formatDistance(metrics.distance13)}`,
        `∠123 夾角：${metrics.angle123.toFixed(2)}°`
    ]);
};

// 處理比例尺縮放因子改變
const handleScaleFactorChange = (newScaleFactor) => {
    setScaleFactorState(newScaleFactor);
    if (isCalculated) {
        recalculateWithScaleFactor(newScaleFactor);
    }
};
```

## 技術要點

### 1. React Hooks 閉包陷阱

這是經典的 React Hooks 閉包問題：

**問題原因：**
- JavaScript 閉包特性 + React 重渲染機制
- 函數捕獲定義時的變量值，而非最新值

**解決方案：**
1. 使用函數式更新：`setState(prev => ...)`
2. ✅ **將 state 作為參數傳入函數**（本次使用）
3. 使用 `useCallback` 並正確設置依賴項
4. 使用 `useRef` 存儲最新值

### 2. 事件處理器參數問題

**常見錯誤：**
```javascript
// ❌ 錯誤：Event 對象被當作參數使用
const handler = (param) => { /* 使用 param */ };
<button onClick={handler}>Click</button>
// 實際上 param 接收到的是 Event 對象

// ✅ 正確方式 1：使用箭頭函數包裝
<button onClick={() => handler(actualParam)}>Click</button>

// ✅ 正確方式 2：不接收參數，使用狀態值（本次使用）
const handler = () => { /* 使用 state */ };
<button onClick={handler}>Click</button>
```

### 3. 最佳實踐

1. **計算函數應該純淨** - 接收所有需要的數據作為參數
2. **明確的參數傳遞** - 讓數據流向清晰可見
3. **避免隱式依賴** - 減少對外部變量的依賴
4. **事件處理器設計** - 明確區分事件對象和業務參數
