要實現登出功能並根據 `userId` 清除 JWT token，JWT 本身的無狀態特性使得它無法直接被從伺服器端刪除。
解決方案是結合一個**伺服器端黑名單**來實現登出邏輯，
登出時將該 `userId` 的 token 添加到黑名單中，並在驗證 token 時檢查黑名單。

以下是完整實現：

---

### **修改 `jwt.js`**
#### **新增黑名單**
使用一個內存數據結構（如 `Set`）來暫存已登出的 token，也可以用 Redis 或數據庫存儲黑名單以支持分佈式系統。

```javascript
const jwt = require('jsonwebtoken');
const SECRET_KEY = 'SECRET_KEY';

/* 黑名單存儲登出的 token */
const tokenBlacklist = new Set();

/* 產生 jwt token */
exports.createToken = (payload, expiresIn = '5m') => {
    return jwt.sign(payload, SECRET_KEY, { expiresIn });
};

/* 驗證 jwt token */
exports.verifyToken = (token) => {
    if (!token) return;
    try {
        // 檢查 token 是否在黑名單中
        if (tokenBlacklist.has(token)) {
            console.log("Token 已失效（黑名單）。");
            return null;
        }
        return jwt.verify(token, SECRET_KEY);
    } catch (err) {
        console.log("驗證 jwt token err : ", err);
        return null;
    }
};

/* 註銷（將 token 添加到黑名單） */
exports.logoutToken = (token) => {
    if (token) {
        tokenBlacklist.add(token); // 添加到黑名單
        console.log("Token 已加入黑名單：", token);
    }
};
```

---

### **登出邏輯**
在你的控制器中，處理登出請求時執行以下操作：

```javascript
// src/controllers/auth.api.controller.js
const jwtUtils = require('../utils/jwt');

exports.logout = (req, res) => {
    const token = req.headers.authorization?.split(' ')[1]; // 獲取 Authorization 標頭中的 token
    if (!token) {
        return res.status(400).json({ success: false, message: "未提供 token" });
    }

    jwtUtils.logoutToken(token); // 將 token 添加到黑名單
    res.status(200).json({ success: true, message: "已成功登出" });
};
```

---

### **登出後驗證 token**
在驗證 token 的邏輯中，會自動檢查是否在黑名單中：

```javascript
// src/controllers/protected.api.controller.js
const jwtUtils = require('../utils/jwt');

exports.protectedEndpoint = (req, res) => {
    const token = req.headers.authorization?.split(' ')[1];
    if (!token) {
        return res.status(401).json({ success: false, message: "未提供 token" });
    }

    const user = jwtUtils.verifyToken(token);
    if (!user) {
        return res.status(401).json({ success: false, message: "token 已失效或無效" });
    }

    res.status(200).json({ success: true, message: "成功訪問受保護的端點", user });
};
```

---

### **測試流程**
1. **產生 Token**
   ```javascript
   const token = jwtUtils.createToken({ userId: 123 });
   console.log("Token:", token);
   ```

2. **訪問受保護的端點**
   使用 `token` 訪問受保護的端點，應成功返回用戶信息。

3. **登出**
   發送 `logout` 請求，將該 `token` 加入黑名單。

4. **驗證登出效果**
   再次使用相同的 `token` 訪問受保護的端點，應返回 `token 已失效或無效` 的錯誤。

---

### **進階改進**
1. **使用 Redis 儲存黑名單**：
   - 適用於多實例應用程序或分佈式架構。
   - 可以基於 token 的有效期設置 Redis 的自動過期時間。
   
2. **基於用戶 ID 清除 Token**：
   如果一個用戶有多個 token，可以在黑名單中存儲 `userId`，並在驗證時檢查是否該 `userId` 被登出。

3. **改用短期 token + 刷新 token 機制**：
   使用短期有效的 token 和持久的刷新 token，避免頻繁驗證黑名單，提升性能。

---

### **注意事項**
- **內存黑名單的局限性**：當伺服器重啟時，內存中的黑名單會被清空，因此更推薦使用 Redis 或數據庫存儲黑名單。
- **黑名單持久化成本**：隨著登出操作增多，黑名單可能會變得龐大，定期清理過期的 token 可以優化資源使用。
