小g 詳細說明 :

在设计一个购物车网站后台，使用 JWT 验证时，需要在新增商品的流程中获取 `userId` 并存入数据库。以下是精简的说明：

### **流程分析**
1. **JWT 验证与解码**：
   - 在用户登录后，服务器会生成一个包含 `userId` 的 JWT，并返回给前端，
        通常存储在 `Authorization` header 中。
   - 后端的每个受保护 API（如新增商品）需要验证该 JWT 是否有效，并从中解码出 `userId`。

2. **获取 `userId` 的时机**：
   - **后端验证中提取**：
     - 在后端的 API 控制器中，可以通过中间件（middleware）统一验证 JWT，并将解码后的 `userId` 附加到 `req` 对象中。
     - 示例：
       ```javascript
       const jwt = require('jsonwebtoken');
       
       function authMiddleware(req, res, next) {
           const token = req.headers.authorization?.split(' ')[1];
           if (!token) return res.status(401).send('Unauthorized');
           
           try {
               const decoded = jwt.verify(token, process.env.JWT_SECRET);
               req.userId = decoded.userId; // 将 userId 附加到 req 对象
               next();
           } catch (err) {
               return res.status(403).send('Invalid token');
           }
       }
       ```
     - 在新增商品的 API 中直接从 `req.userId` 获取。

3. **存储商品时使用**：
   - 在新增商品的请求体中，`userId` 不需要由前端提供（避免被篡改），而是从 `req.userId` 中获取，并自动附加到商品数据中：
     ```javascript
     app.post('/api/products', authMiddleware, async (req, res) => {
         const { name, price, description } = req.body;
         const userId = req.userId; // 从中间件获取的 userId
         const product = { name, price, description, userId };
         
         // 保存到数据库
         await db.collection('products').insertOne(product);
         res.status(201).send('Product added successfully');
     });
     ```

### **总结**：
- **提取时机**：通过 后端 中间件统一验证和解码 JWT，从中提取 `userId`。
- **存储时机**：在新增商品的 API 处理逻辑中，将 `userId` 自动附加到商品数据中。
- **优点**：用户身份的验证和关联逻辑全由后端控制，确保数据安全性并防止篡改。
