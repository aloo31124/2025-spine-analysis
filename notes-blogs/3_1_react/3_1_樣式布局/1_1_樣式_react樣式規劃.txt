为了避免 CSS 样式互相污染或污染全局，可以采用以下方法规划和设计样式，并在项目中引用：

---

### **规划设计：**
1. **局部样式文件化**  
   - 每个组件的样式文件单独维护，与组件放在同一目录下。  
   - 命名方式建议采用 `ComponentName.module.css` 或 `ComponentName.css`。

   ```
   src/
   ├── components/
   │   ├── Header/
   │   │   ├── Header.jsx
   │   │   └── Header.module.css
   │   ├── Footer/
   │   │   ├── Footer.jsx
   │   │   └── Footer.module.css
   │   ├── SearchBar/
   │   │   ├── SearchBar.jsx
   │   │   └── SearchBar.module.css
   ```

2. **使用 CSS Modules**  
   - 通过 CSS Modules，样式作用域会限定在当前组件，避免污染全局。  
   - 样式类名会自动生成唯一标识符。

3. **命名规范**  
   - 使用 BEM（Block-Element-Modifier）命名规则，与 CSS Modules 配合更清晰。  

---

### **撰写与引用局部样式：**

#### **1. 使用 CSS Modules：**
```jsx
// Header.module.css
.header {
  background-color: #f8f9fa;
  padding: 10px;
}

.logo {
  font-size: 24px;
  color: #333;
}
```

```jsx
// Header.jsx
import React from 'react';
import styles from './Header.module.css';

function Header() {
  return (
    <header className={styles.header}>
      <h1 className={styles.logo}>My Logo</h1>
    </header>
  );
}

export default Header;
```

#### **2. 使用 Styled Components (CSS-in-JS)：**
- 利用第三方库 `styled-components`，在 JS 中直接写样式，具有动态性和作用域隔离优势。

```jsx
// Header.jsx
import styled from 'styled-components';

const HeaderContainer = styled.header`
  background-color: #f8f9fa;
  padding: 10px;
`;

const Logo = styled.h1`
  font-size: 24px;
  color: #333;
`;

function Header() {
  return (
    <HeaderContainer>
      <Logo>My Logo</Logo>
    </HeaderContainer>
  );
}

export default Header;
```

#### **3. 使用全局类名的局部限定：**
- 通过前缀区分，避免命名冲突。  

```css
/* Header.css */
.header-container {
  background-color: #f8f9fa;
  padding: 10px;
}
```

```jsx
import React from 'react';
import './Header.css';

function Header() {
  return (
    <header className="header-container">
      <h1>My Logo</h1>
    </header>
  );
}

export default Header;
```

---

### **比较：**
| 方法               | 优点                                    | 缺点                          | 适用场景                     |
|--------------------|-----------------------------------------|-------------------------------|------------------------------|
| **CSS Modules**    | 样式局部化，简单易用，类名自动生成唯一性 | 配置复杂度略高，需额外打包支持 | 推荐用于大多数项目           |
| **Styled Components** | 动态样式支持强，CSS 直接写入组件中       | 增加运行时开销，依赖第三方库   | 动态样式需求多，设计系统场景 |
| **全局类名前缀区分** | 无需特殊配置，易于维护                 | 样式可能仍会全局影响           | 小型项目或已有项目的渐进改进 |

通过上述方法，结合项目需求选择合适的样式管理方式，可以有效避免 CSS 样式污染，提高代码的可维护性。
