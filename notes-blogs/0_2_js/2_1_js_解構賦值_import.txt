js 如下兩寫法, 業界中英稱呼為何? 優缺點為何?
並提供相關官方文章

寫法1:
    const {getProductList, ...} = require('../../services/product.service');
    exports.getProductList = async (req, res) => {
        res.status(200).json({result:'200', productList: await getProductList()});
    };

寫法2:
    const productService = require('../../services/product.service');
    exports.getProductList = async (req, res) => {
        res.status(200).json({result:'200', productList: await productService.getProductList()});
    };


----------------------------

### **業界中英稱呼**
    1. **寫法1**：**Destructuring Assignment (解構賦值)**  
    - 從模組中直接解構出需要的函數或變數。

    2. **寫法2**：**Namespace Import (命名空間導入)**  
    - 將整個模組導入並透過命名空間存取其成員。

    ---

### **優缺點比較**

    #### **寫法1：Destructuring Assignment**
    **優點**：
    1. **簡潔性**：直接解構出需要的函數，程式碼更簡潔。
    2. **可讀性**：明確指出使用哪些函數，便於理解。
    3. **減少錯誤**：避免誤用模組中未導入的函數。

    **缺點**：
    1. **維護性**：若模組新增或刪除函數，需手動更新解構部分。
    2. **彈性不足**：無法動態存取模組中的其他成員。

    #### **寫法2：Namespace Import**
    **優點**：
    1. **彈性高**：可動態存取模組中的所有成員。
    2. **維護性**：模組新增或刪除函數時，不需修改導入部分。
    3. **命名衝突少**：透過命名空間避免與其他變數衝突。

    **缺點**：
    1. **冗長**：每次呼叫函數都需寫完整命名空間，程式碼較冗長。
    2. **可讀性差**：無法一眼看出使用了哪些函數。

    ---

### **使用場景**
    1. **寫法1**：適合明確知道需要哪些函數，且模組成員較少的情況。
    2. **寫法2**：適合模組成員多、需動態存取，或模組成員可能變動的情況。

---

### **相關官方文章**
    1. **Destructuring Assignment**：
    - [MDN - Destructuring Assignment](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Destructuring_assignment)
    - [Node.js Modules - Destructuring](https://nodejs.org/api/modules.html)

    2. **Namespace Import**：
    - [Node.js Modules - Require](https://nodejs.org/api/modules.html#modules_require)
    - [JavaScript Modules - Import](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import)

---

### **總結**
- **寫法1**：簡潔、明確，適合小型專案或固定模組成員。
- **寫法2**：彈性高、維護性好，適合大型專案或動態存取需求。
- 選擇時需根據專案規模、模組複雜度及團隊習慣決定。
